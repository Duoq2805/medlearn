Authentication System Overview

1. Feature Overview

The Authentication System is a critical component of the Medvora platform, responsible for securely managing user access. It supports distinct roles (User, Reviewer, Admin) and utilizes JWT for stateless authentication. The system is designed to be scalable, maintainable, and secure, adhering to clean architecture principles.

2. Current Architecture

The backend follows a layered architecture:

Controller
    ↓
Service
    ↓
Repository
    ↓
Database

Key Components:

  • Controllers: Handle incoming API requests, delegate to services. Thin, no business logic.
  • Services: Contain core business logic, use DTOs, exceptions, and transaction management.
  • Repositories: Data access layer using Spring Data JPA, handling entity interactions and soft deletes.
  • DTOs: Data Transfer Objects for API communication (requests/responses).
  • Entities: JPA entities representing database tables.
  • Security: JWT implementation, role-based access control (@PreAuthorize), SecurityFilterChain, CurrentUserResolver.
  • Mappers: MapStruct for converting between Entities and DTOs.

3. Authentication Workflow

Authentication Flow:

  1. User sends credentials (e.g., email/password) to the auth controller.
  2. Auth controller delegates to the AuthService.
  3. AuthService validates credentials, checks user status, and generates a JWT.
  4. JWT is returned to the client.
  5. Subsequent requests include the JWT in the Authorization header.
  6. A filter intercepts requests, validates the JWT, and extracts user details.
  7. User information is available via CurrentUserResolver.

Role-Based Access:

  • Access to certain endpoints is protected by @PreAuthorize annotations based on user roles (USER, REVIEWER, ADMIN).

5. Completed Work (Authentication Enhancements)

  • Core JWT generation and validation (HS256, jjwt 0.12.6).
  • User registration + email verification flow.
  • Resend email verification — POST /api/auth/resend-verification.
  • Timing-safe login (always run BCrypt even for unknown email).
  • Refresh token with reuse detection → revoke all sessions.
  • Logout via refresh token body.
  • Password reset flow — POST /api/auth/forgot-password + POST /api/auth/reset-password.
  • JWT error differentiation — Expired / Malformed / Signature / Generic → typed log + clearContext.
  • Login rate limiting — in-memory, 5 attempts / 15min block.
  • Spring Security auth failures → 401, Access denied → 403, Rate limit → 429.
  • MapStruct UserMapper (User → UserDTO), /me không lộ entity.
  • Role-based access via @PreAuthorize + @EnableMethodSecurity.

7. Constraints & Important Rules

  • JWT authentication with Bearer token (HS256).
  • Stateless session (SessionCreationPolicy.STATELESS).
  • Strict adherence to layered architecture (Controller → Service → Repository → Database).
  • Use DTOs for all API communication; never return entities directly.
  • Maintain API compatibility during changes.
  • Sensitive data must not be exposed or hardcoded.
  • Follow established Naming and Package Structure rules.

8. Reusable Patterns

  • JWT Generation/Validation (JwtService).
  • Layered Architecture (Controller-Service-Repository).
  • DTO-centric API communication.
  • Custom Exception Handling via GlobalExceptionHandler.
  • Role-based access control with @PreAuthorize.
  • Soft Deletes for entities.
  • MapStruct for entity-DTO mapping.

## Conventions đang dùng

- Layered: Controller (thin) → Service interface / impl → Repository → Entity
- DTOs: @Data + Jakarta Validation (request); @Data @Builder (response)
- ApiResponse wrapper cho tất cả endpoints
- Constructor injection via @RequiredArgsConstructor
- Soft delete: deletedAt + @SQLRestriction
- Enums: @Enumerated(EnumType.STRING)
- Timestamps: OffsetDateTime + @CreationTimestamp / @UpdateTimestamp
- @Version optimistic locking
- @Transactional trên write operations
- @Async cho email
- @Scheduled cleanup (AuthServiceImpl, 1h interval)

## Constraints quan trọng

- KHÔNG hardcode secrets
- KHÔNG return entity trực tiếp từ API
- KHÔNG đặt business logic trong Controller
- Security sensitive responses (forgot-password, resend): same message bất kể email tồn tại không
- Refresh token reuse: check revokedAt TRƯỚC expired/deactivated
- Login: luôn chạy passwordEncoder.matches() dù user không tồn tại (timing-safe)
